Measure independent directions

A square can shrink equally in two directions, or change width and height by different amounts. Extract both axes rather than inferring one from the other.

Scale ratio = output length / reference length.
Signed error (%) = 100 x (output - reference) / reference.

Measure the path centre line. Line thickness, screen zoom and screenshot pixels are different quantities. Use a physical ruler to check a real print.

What the A4-to-Letter model assumes

The whole-paper model uses min(215.9 / 210, 279.4 / 297), with no margins or printer restrictions. Its scale is about 94.0741%. It is a mathematical control, not an observed print setting result. A printable-area fit can differ.

Run an actual software comparison

  1. Open the PDF reference in the application you want to test.
  2. Open the visible print UI. Record the exact application, destination, paper, orientation and scale labels. Capture a settings screenshot.
  3. Save the actual output. Keep the original PDF and screenshot, including SHA-256 hashes.
  4. Inspect width and height independently, then visually review clipping and page boundaries.

Destination matters. Chromium documents a source-size path for Save as PDF. It can retain the PDF's original page size, which is different from printing to a PDF printer destination. If the UI does not expose paper or scale controls, record that fact instead of inventing applied settings.

Suggested cases: matched A4 at Actual size; matched Letter at Actual size; A4 to Letter at Fit to paper; Letter to A4 at Fit to paper. Use only controls that actually exist in the captured destination.

No native outcome is listed until a real output and settings receipt have been measured.

Reproduce the geometry checks

The generator and analyzer are downloadable Python scripts. Their control results should not be mistaken for an application benchmark.

python build_atlas.py
python inspect_pdf_geometry.py --all-generated
python inspect_pdf_geometry.py --native-receipt incoming/your-case.receipt.json
